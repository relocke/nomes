# Development roadmap

## Available in this project

- A local, schema-valid `nome.json` with stable identity and discovery metadata.
- A reference map for maintained definitions, skills, harnesses and runtimes.
- A website directory entry, manifest-driven conversation space and project download.
- Reuse of Forge's existing conversation, file review and local-folder saving.
- A growing `CONTEXT.md` document, updated through reviewed conversation proposals.

## Proposed next steps

1. Review the mission and agree which changes this Nome governs.
2. Define responsibility, licence and acceptance criteria with evidence.
3. Add structured, revision-pinned references through a reviewed schema extension
   if Markdown references no longer meet the project's needs.
4. Build a permission-aware discovery index and read-only MCP Nome search, subject
   to explicit authorization for protected MCP changes.
5. Evaluate model comparisons with recorded prompts, revisions and disagreements;
   separately authorize any required runtime or harness integration.
6. Design reversible conversation summaries and review queues with provenance,
   correction and recovery. Do not equate hidden content with deleted content.

These are proposals, not installed capabilities. Changes to protected components
require explicit owner authorization for their specific scope.

## Discovery metadata

`nome.json` now declares reusable SEO metadata, agent orientation and optional
revision-pinned relationships. Read `DISCOVERY.md` for the field contract, website
rendering and capability limits; `AGENTS.md` provides concise agent orientation.
Automatic hierarchy traversal and dedicated MCP resources remain planned.
